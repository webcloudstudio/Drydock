Build working software from specifications —

Ed Barlow · Web Cloud Studio

The problem

AI writes code fast.
Nobody can govern it.

  • Agents emit a thousand lines from a prompt — then the spec drifts from the code.
  • The context window fills with the wrong files. Yesterday's decisions are forgotten.
  • Great for a demo. Terrible for a product.

The bottleneck was never the model. It's context, governance, and drift.

The insight

Context management is the key to reproducible builds.

Control exactly which files the model sees — in what order, under what intent — and you get the same quality build every time. The specification stays the single source of truth.

SA · ANALYZEIL

Charting the course

Sources→ import→ analyze→ ANALYSIS.md
  • Import markdown, source code, Spec Kit, or loose notes.
  • Decompose into stories, acceptance milestones, blockers, questions — using agile.
  • Find a blocker → stop and ask. You answer, you re-run, until the plan is genuinely ready.
The differentiator

The QuarterDeck:
review before you build.

A local web console that renders everything the LLM produced — the analysis, the story hierarchy, the blockers, the questionnaires.

  • Approve, answer, redirect. Answers are written back to the spec.
  • Carried into every future run — decisions never get lost.
  • The human-in-the-loop checkpoint vibe coding doesn't have.
The engine

The Manifest:
a dependency graph of your build.

  • drydock plan turns the analysis into typed Blueprints + the Manifest.
  • The LLM gives an exact token cost for every story.
  • Drydock stacks exactly the right files into each prompt — intent, the relevant spec slice, the task — under a context budget you set.

Context is engineered, not hoped for. That's how builds become reproducible.

SAI · IMPLEMENTL

Sailing the frontier

  • drydock build walks the graph and builds the runnable frontier, one step at a time.
  • Every step produces reviewable evidence. Verify against acceptance criteria → unlock dependents.
  • drydock build score measures delivery health across seven dimensions — spec completeness, test coverage, drift, and more.

SAIL · LOOP

The refit

Software is never done. drydock refit changes the application while keeping the Blueprint and the code aligned.

  • Tracks the git commit behind every built file — rebuilds only what changed.
  • The spec stays the source of truth. Docs regenerate from it. Nothing drifts.
