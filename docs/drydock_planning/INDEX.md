# Drydock Adversarial Assessment

## Executive Assessment

Drydock's spine is coherent — Blueprint as source of truth, Manifest as build state, deterministic proofs, Commander review — and the Artifact I/O Matrix is unusually well specified. The failures are in the enforcement surface, not the model. The two contracts that actually govern generation contradict the specification on whether `ac` blocks are legacy or mandatory, on whether the ordering header field is `Phase` or `Build Order`, and on whether SCREEN `Route` is required; prompts repeatedly promise deterministic rejection ('Drydock rejects this defect at `drydock validate`', 'the plan is rejected') with no artifact tying any claim to a check. Test-driven delivery is asserted more than enforced: the specification advertises 'Pre-Build RED->GREEN enforcement' while its own Execution Rules say the pre-build observation 'does not block the build', and `plan_create.md` defines every story's mandatory gate as 'a smoke check that runs the project test suite' — the same non-discriminating command for every story. Context economy is claimed but never computed: `plan_create.md` orders the model to 'Keep a group's combined size within the context ceiling' without supplying the ceiling, and demands the entire Blueprint plus `MANIFEST.md` in one strictly-parsed, un-resumable response against a 100-story cap. Outside route-shaped web and CLI work the dependency graph has no grammar at all — `BLUEPRINTS_CONTRACT.md` extracts `Provides` from route tables — so pipelines, event systems, libraries, and ML projects degrade into undifferentiated prose in `FEATURE-*.md` with no computed edges and no expressible acceptance.

## Systemic Risks

- Total plan loss on truncation: `plan_create.md` requires every Blueprint file plus MANIFEST.md in a single response parsed strictly by `artifact_blocks.py`, with no partial commit, no resume, and no per-file retry — the most expensive call in the pipeline is the most brittle, and it is assigned `model: sonnet` with no `effort:`.
- Non-discriminating story gates: the mandatory child `ac` is canonically 'a smoke check that runs the project test suite', identical for every story, so a story that delivered nothing and a story that delivered everything close on the same evidence.
- Proofs that cannot run rather than proofs that fail: `Programmatic Acceptance` has no declared environment, service lifecycle, port allocation, fixture, isolation, or timeout, yet plan_create requires SCREEN proofs to 'literally call every route' — which needs a running app. Mass UNVERIFIED becomes indistinguishable from mass non-delivery.
- RED is never enforced: the specification's Execution Rules state a pre-build pass 'does not block the build' and is only 'weak evidence', while the build agent writes the implementation and the tests that prove it in the same step. Nothing prevents acceptance that was green before a line was written.
- Contract divergence between `Drydock_Specification.md`, `MANIFEST_CONTRACT.md`, and `BLUEPRINTS_CONTRACT.md` (legacy vs mandatory `ac`, `Phase` vs `Build Order`, SCREEN `Route` required vs optional, `depends:` comma- vs space-separated) means a conforming plan may be rejected and a nonconforming plan accepted, with no document the Commander can point to as the winner.
- Unbounded build steps: no deterministic per-block prompt cost is computed at plan time despite `build.py` being 'the single deterministic prompt/cost subroutine'. Oversize blocks are discovered one at a time, mid-build, at full cost — exactly the case the specification claims to serve ('Build large projects with low-end models').
- Refit tickets are never reconciled into the parent spec, so `applied_specs` sha256 stays clean while the Blueprint stops describing the software that `document generate` and `score release` read it to assess.
- No dependency grammar for non-route shapes: `BLUEPRINTS_CONTRACT.md` computes `Provides` from route tables only, so for pipelines, event systems, and libraries the frontier order is authored guesswork and 'dependency-aware build order' is unearned.
- Self-reported build evidence: `build.md` makes the agent author its own `FILES CHANGED` and `RESULT`, and `score_release.md` is then told that record 'is the complete assessment record' — the assessed party writes the evidence.
- Repair passes optimize to the literal assertion: `--repair-attempts` and `--escalate-model` exist with no repair-specific prompt and no anti-overfit signal, so the cheapest path to green is narrowing the implementation until the declared proof passes.
- `plan_conform.md` runs per-file with `inputs: SPEC_FILE` only — `BLUEPRINTS_CONTRACT.md` is never injected — and emits bullet-list acceptance that violates the contract's required `### check-id` + fenced-python shape, producing conformed specs whose proofs can never execute.
