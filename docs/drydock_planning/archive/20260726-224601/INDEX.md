# Drydock Adversarial Assessment

## Executive Assessment

Drydock's spine is sound: a typed Blueprint as source of truth, a dependency-ordered Manifest, digest-tracked applied specs, and a deterministic acceptance runner are the right primitives, and the Specification is unusually honest about where the process gates. The failure is that most of the governance is prose addressed to the model that is being governed. `plan_create.md` declares roughly a dozen conditions under which `the plan is rejected`, but the rejecting party is the same model that emitted the plan; `Pre-Build RED->GREEN enforcement` is listed as a Verification feature while the Execution Rules state a pre-passing proof `does not block the build`; and `build.md` closes with a self-attested `FILES CHANGED` list that nothing reconciles against the filesystem. Two contracts contradict each other outright — the Specification calls `ac` a legacy block type while `MANIFEST_CONTRACT.md` and `plan_create.md` reject any story lacking one, then define that mandatory gate as a full-suite run that the same prompt forbids from non-terminal stories. Sea Trials guardrails are exempted from planning coverage and simultaneously fatal at release scoring, so a plan that follows the contract exactly is engineered to fail its own gate. Outside Python the whole TDD goal is unreachable, because acceptance is defined as Python fenced blocks in the contract itself, not merely in Rigging — the extension point the Specification advertises does not reach the acceptance runner.

## Systemic Risks

- Self-adjudicated planning: every `is rejected` rule in `plan_create.md`, `plan_reuse.md`, and `MANIFEST_CONTRACT.md` is enforced by the emitting model, so a malformed Manifest — dangling `parent:`, forward `depends:`, uncovered Sea Trial, story with no proof — reaches `drydock build` and is discovered as a build failure instead of a plan defect.
- Acceptance that cannot fail: `proof_integrity.py` demotes only empty bodies, constant assertions, and self-comparisons, while the dominant vacuous forms — `Path(...).is_file()`, bare imports, `subprocess.run` with no assertion on output, grepping the source for its own literals — score as PASS and lift the release verdict.
- RED baseline is advisory: `Drydock may run the same Programmatic Acceptance before the build as an observation... This does not block the build`, so a build agent can satisfy a Definition of Done that was already green, and the Specification's advertised RED->GREEN enforcement is not a gate.
- Guaranteed release-gate deadlock: guardrail Sea Trials `require no story or proof reference` at plan time, and `score_release.md` fails any guardrail lacking positive evidence as UNPROVEN, so conformant plans cannot pass release scoring.
- Unbounded build cost: the documented `while drydock status --ready; do drydock build; done` loop plus `--continue` resuming a failed block in place has no durable per-block attempt budget, so an environmental failure re-issues the same expensive LLM call indefinitely.
- Silent context staleness: compaction freshness is an mtime warning with a documented `touch` workaround, so a build can inject a superseded `DATABASE_compact.md` and implement a dead interface with no drift signal.
- Unverified build evidence: `RESULT: SUCCESS` and `FILES CHANGED` are model self-reports; nothing reconciles them against a real diff of the build directory, so a step that wrote nothing can close a story.
- No context budget until it is too late: story size is defined as `the token and context size of the build step` and feature grouping is bounded by an unnamed `context ceiling`, but neither is computed at plan time, so oversized blocks are discovered by truncation during the build.
- Cross-cutting behavior has no owner: no Typed Specification file type covers auth, tenancy, PII, rate limiting, or audit, so the highest-risk invariants in a real product exist only as release-time Sea Trials nobody builds.
- Python monoculture in the contract, not just in Rigging: acceptance is defined as Python fenced blocks executed as scripts, so supplying non-Python Rigging still leaves a project unable to express its Definition of Done.
