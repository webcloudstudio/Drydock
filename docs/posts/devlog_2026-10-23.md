**Acceptance Criteria define the Definition of Done.**

**The Builder loops to create correct software.**

Drydock turns your specifications into Blueprints, executable acceptance criteria, and working
software. A **Verify and Repair Loop on Acceptance Criteria** tests the implementation, feeds
failures back to the Builder, and measures each repair. Earlier stories run again as
**regression gates**.

Since the 0.2 beta:

- **Acceptance Criteria Testing Framework.** Every story requires executable acceptance criteria.
  Malformed, ineffective, and flaky checks are identified so test defects do not masquerade as
  product failures.
- **Full UAT Harness.** Runs the complete delivery lifecycle against test projects, with
  resumable stages, independent acceptance gates, and portable evidence bundles with SHA-256
  checksums.
- **Generated, encapsulated persistence.** `DATABASE.md` defines schemas and named operations.
  Drydock generates Python and Go persistence packages for SQLite and PostgreSQL; features call
  declared interfaces instead of embedding SQL.
- **Diagnosis and repair.** `drydock diagnose` identifies root causes and proposes Blueprint
  corrections. `--apply` updates the Blueprints and resets affected work for rebuilding.
- **Controlled change.** REFIT tickets connect change requests to their Blueprint owners and
  queue the work in dependency order.
- **Model choice and delivery evidence.** Claude, Codex, and Gemini support; model-specific token
  budgets; specification-to-code lineage; and reports showing progress, acceptance results, and
  model usage.

**Use Drydock to make “done” executable: specify the behavior, build it, verify it, and repair
what fails.**

Still beta. Final UAT is in progress before publication. **Patent application filed.**
