### **What is Drydock**
  * Build Software (Go or Python) from Your Specifications using low-end models (Haiku 5.5, Luna, or Gemini). <br>
  * Based on **Agile Decomposition** and **Test Driven Development**.
  * `drydock run quarterdeck` is a complete web UX for your builds.
---
### **New Feature: Measured, self-correcting acceptance criteria**
  * `drydock plan repair` measures, categorizes, and corrects acceptance criteria.
### **New Feature: Self-Improving Builds**
  * `drydock diagnose` reads failed runs, identifies the root cause, and proposes corrections. 
  * `drydock build` iterates until all Acceptance Criteria succeed or no progress is detected.
### **New Feature: Encapsulated Persistence Layer**
  * `DATABASE.md` uses a pre-built native library plus named SQL operations to minimize change impact radius.
### **New Feature: Updated Drydock workflow**
  * `drydock_runner.sh` is the minimal self-repairing workflow to build anything.
```bash
drydock init MyApp                            # create the workspace
drydock import MyApp "$INPUT_DIRECTORY"       # load your specifications
drydock analyze MyApp                         # create stories, questions, blockers
drydock plan MyApp                            # create Blueprints and Manifest
drydock plan verify MyApp || drydock plan repair MyApp  # repair/validate acceptance criteria

# implement build as a self-repairing loop
n=1; max=5
while drydock status MyApp --ready
do
    echo "*** BUILD ATTEMPT $n ***"
    drydock build MyApp || drydock diagnose MyApp --apply
    n=$((n+1))
    if [ "$n" -gt "$max" ]
    then
        echo "hit $max build attempts - aborting"
        exit 1
    fi
done
drydock status MyApp --check                  # done when every block is closed
drydock score release MyApp                   # does the project meet its AC
```

### **Release Notes:** 
- This is a big release - a few hundred commits.  
- Haiku 5.5 works great:  
  - Auto-escalates to Sonnet over 100K tokens (for pricing reasons). 
  - Use `--plan-override-model sonnet` due to Haiku's poor planning skills. It builds fine, but... 
- **Version 0.9** will overhaul the **refit process** to enterprise standards (my plan is to be best of breed).   
- **GA Release** will offer a **full User Experience via the QuarterDeck Web Server - no CLI commands required**. 
  - Refit has not been touched this version, as it is its own release. 
- Memory Files added, controlled by `AGENTS.md`. 
- The new UAT Test Suite contains 10 projects tested under Haiku and Luna - I hope this is sufficient to catch all errors. 
- The database encapsulation is for SQLite and Postgres, but it's pretty easy to add other databases - Postgres instructions are provided.
- Full Go and Python support - I just don't have other languages on my box, so make suggestions on what you want.
- Model token cost engineering optimizes both fixed and variable context payload size - calibration in `model_config.jsonl`. 
- Gemini added as a third provider.
- Six-tier Blueprint build hierarchy: Foundation, database, web server, CLI, branding, interface, and screens. 
- `BUILD_LINEAGE.jsonl` traces specifications to code for every agent run.
- `drydock report` has seven deterministic reports, including `report token`.
- Model effort: Haiku 5.5 runs at a set effort level, and each model row in `model_config.jsonl` can set `effort`.
