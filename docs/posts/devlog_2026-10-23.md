## Updated Drydock workflow

Basic project build loop, including acceptance-criteria verification and repair:

```bash
drydock init MyApp                            # create the workspace
drydock import MyApp "$INPUT_DIRECTORY"       # load specifications
drydock analyze MyApp                         # stories, questions, blockers
drydock plan MyApp                            # Blueprints and Manifest
drydock plan verify MyApp || drydock plan repair MyApp  # repair acceptance criteria

n=1; max=5
while drydock status MyApp --ready
do
    echo "*** BUILD ATTEMPT $n ***"
    drydock build MyApp || drydock diagnose MyApp --apply
    n=$((n+1))
    if [ "$n" -gt "$max" ]
    then
        echo "hit $max build attempts - aborting"
        exit 1
    fi
done
drydock status MyApp --check                  # done when every block is closed
drydock score release MyApp                   # release gate
```

## drydock diagnose — Diagnosis and Repair Loop

**`drydock diagnose`** reads a failed run, identifies the root cause, and proposes Blueprint
corrections with evidence and next steps. **`--apply`** repairs selected defective acceptance
criteria and applies verified corrections. Blockers and decisions identify where Commander
input is required.

```bash
drydock diagnose MyApp --apply                # diagnose and apply repairs
```

## Encapsulated Persistence Layer

**Keep application changes out of the database and database changes out of the application.**
`DATABASE.md` defines named operations with input and output contracts. Features use those
contracts instead of tables or SQL, isolating schema changes and avoiding unnecessary rebuilds.
