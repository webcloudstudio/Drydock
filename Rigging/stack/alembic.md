# Alembic Migration Discipline

**Type:** guidance
**Version:** 20260909 V1
**Category:** Persistence
**Description:** Alembic revision, upgrade, downgrade, and verification rules for SQLAlchemy applications.

Technology reference. Apply when a Python Target has relational persistence.

Prerequisites: `languages/python/python.md`, `stack/sqlalchemy.md`

---

## Source of Truth

Alembic revisions in `migrations/versions/` are the schema history. Production and development
schemas advance only through `alembic upgrade head`. Application startup does not alter schema.

```bash
uv add sqlalchemy alembic
uv run alembic init migrations
uv run alembic revision --autogenerate -m "add project status"
uv run alembic upgrade head
```

Autogenerated revisions are drafts. Review every generated operation, data backfill, index,
constraint name, upgrade, and downgrade before committing.

## Contract Classification

Classify the matching `DATA-*` contract in `DATABASE.md`:

| Level | Meaning |
|-------|---------|
| `unchanged` | The revision is physically visible only; repository input, output, type, nullability, and behavior stay stable. |
| `data` | A repository input/output type or nullability changes. |
| `rebuild` | A repository call, required input, returned field, or semantic behavior changes. |

A `NULL` to `NOT NULL` revision is `unchanged` only when the repository preserves its public
contract, including a safe data backfill. Otherwise it is `data`.

## Verification

- Upgrade an empty database to `head`.
- Upgrade a database at the prior revision to `head`, including required data backfill.
- Run repository contract tests after each upgrade.
- Exercise downgrade when the revision declares it supported.
- Run `uv run alembic check` where the project supports autogeneration checks.
