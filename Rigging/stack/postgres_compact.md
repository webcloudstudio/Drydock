Drydock generates `persistence/testing.py` with the package. `db_session()` opens a fresh store
with `schema.sql` applied. Drydock applies `schema.sql` to the configured store — `DATABASE_URL`,
else `DATABASE_PATH`, else `data/app.db` — at the DATABASE step and before every acceptance run,
so a criterion that drives the application through its own client finds the declared tables.

A criterion imports `db_session` from `persistence.testing` and uses it as a context manager —
`with db_session() as db:` — against the built database layer, without pytest. The pytest
suite receives the same store through the `conftest.py` fixture. Neither opens a connection
of its own.
